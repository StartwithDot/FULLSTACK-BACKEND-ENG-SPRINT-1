# BE06: individual learning workspace

Complete every essential skill yourself. Mistakes here are practice; the single shared product lives in [shared/](../../shared/README.md).

Open the current week's problem statement. It links to the canonical instructions, so the cohort has one consistent task set. Keep code, notes and evidence inside your own BE06 folder. From Week 4 onward, keep the same API entry point and wire later modules into it using the [individual app guide](../../docs/12-application-wiring.md). Later tasks may deliberately continue earlier labs.

- [Week 1](week-01/problem_statement.md): Meet the merchant and make the first change
- [Week 2](week-02/problem_statement.md): Represent events and ask the first SQL questions
- [Week 3](week-03/problem_statement.md): Functions, relational boundaries and first tests
- [Week 4](week-04/problem_statement.md): Cross the HTTP boundary without losing the model
- [Week 5](week-05/problem_statement.md): Receive one event end to end
- [Week 6](week-06/problem_statement.md): Make accepted events survive restart
- [Week 7](week-07/problem_statement.md): Handle repetition and bound the list
- [Week 8](week-08/problem_statement.md): Authenticate a merchant operator
- [Week 9](week-09/problem_statement.md): Enforce merchant ownership across every route
- [Week 10](week-10/problem_statement.md): Build a small merchant interface while tightening responses
- [Week 11](week-11/problem_statement.md): Connect the interface to the protected backend
- [Week 12](week-12/problem_statement.md): Consolidate correctness before adding polish
- [Week 13](week-13/problem_statement.md): Make failures visible and requests bounded
- [Week 14](week-14/problem_statement.md): Investigate, repair and rehearse a clean start
- [Week 15](week-15/problem_statement.md): Demonstrate and hand over the merchant application

Read the [student guide](../../docs/03-student-guide.md). The rotation assigns shared build/review work, not a student specialisation.
