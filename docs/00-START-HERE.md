# Start Here

The client wants a useful merchant event application. The cohort turns that request into a brief, practises the needed skills and assembles one reviewed product.

## What the words mean

- **Sprint:** this entire 15-week project, not a two-week Scrum sprint.
- **Week:** a five-hour learning/build/review block within this sprint.
- **Track:** a recurring skill category, not a specialisation or a separate class to finish first.
- **Individual zone:** your BE folder, where you attempt every core skill.
- **Shared zone:** the one implementation the cohort hands over.

## The working rhythm

Read the project requirement -> research a bounded concept -> attempt a small exercise -> show proof -> promote/review the shared change -> explain a decision.

Each week mixes selected tracks. Language concepts and SQL return in later API, authentication, testing and interface tasks. Frontend work is small and appears where the backend has something useful to show.

## Your first sitting

1. Read [the brief](01-project-brief.md).
2. Follow only setup sections 1-3 in [Windows setup](02-windows-setup.md).
3. Run `npm.cmd ci` and `npm.cmd run check` from the repository root.
4. Find your BE number in [students/](../students/README.md).
5. Open that week's problem statement and follow its canonical link.
6. Make a focused task branch and show your first diff to a peer.

You do not need PostgreSQL before Week 1, prior programming experience, Docker, WSL, a card or an external payment account. JavaScript basics are part of the early TypeScript tasks, not an undisclosed prerequisite course.

## Time and progress

15 weeks is roughly three and a half months and replaces the earlier three-month limit. Each week budgets 90 minutes learning/setup, 150 minutes core tasks, 30 minutes shared build or witness/review, and 30 minutes weekly explanation/revision. These are planning estimates. Ask with evidence if you cannot proceed.

Optional available time is repetition and extra cases. It must not turn into essential ten-hour homework. Everyone has the same 45 core tasks.

## Milestones

- Week 1: Agreed client brief.
- Week 5: First local event flow.
- Week 6: Durable event flow.
- Week 9: Protected merchant flow.
- Week 15: Independent handover.

The witness records what actually works. The teacher reviews risky work such as password/session handling and cross-merchant queries. Every individual practices those concepts regardless of who builds that week's shared version.
