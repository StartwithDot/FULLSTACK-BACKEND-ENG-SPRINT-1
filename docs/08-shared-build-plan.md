# Shared build plan

Every student attempts the week's core tasks. The assigned build pair promotes reviewed work into the shared application; a non-author reviews or reproduces it. Use the [rotation plan](06-team-roles.md) and the week's rotation log.

| Week                      | Shared paths                                                                                                          | Required outcome                                                                                                      |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| [1](../weeks/week-01.md)  | `shared/delivery/brief.md and shared/delivery/context.md`                                                             | A reviewed brief, a safe event summary, and one authored pull request. Milestone: Agreed client brief.                |
| [2](../weeks/week-02.md)  | `shared/delivery/event-contract.md and shared/database/practice-notes.md`                                             | Typed event data, real SQL answers and an explicit input contract.                                                    |
| [3](../weeks/week-03.md)  | `shared/delivery/data-model.md and shared/api/test/contract.test.ts`                                                  | A reusable validation exercise, a relational model and tests that detect a bug.                                       |
| [4](../weeks/week-04.md)  | `shared/api/src/app.ts and shared/delivery/api-contract.md`                                                           | A tiny HTTP application, observable async behavior and an API plan.                                                   |
| [5](../weeks/week-05.md)  | `shared/api/src/routes/events.ts, shared/simulator/send-event.ts and shared/delivery/first-flow.md`                   | A simulator request reaches the API and is visible through a list endpoint. Milestone: First local event flow.        |
| [6](../weeks/week-06.md)  | `shared/database/migrations/, shared/api/src/repository.ts and shared/api/test/persistence.db.test.ts`                | A fresh migration, parameterized storage and a restart proof. Milestone: Durable event flow.                          |
| [7](../weeks/week-07.md)  | `shared/database/migrations/002-event-identity.sql, shared/api/src/repository.ts and shared/api/src/routes/events.ts` | Database-backed duplicate behavior and a stable, bounded listing contract.                                            |
| [8](../weeks/week-08.md)  | `shared/database/migrations/003-operators.sql, shared/api/src/auth.ts and shared/delivery/security-model.md`          | Login, expiry and logout with protected API access.                                                                   |
| [9](../weeks/week-09.md)  | `shared/api/src/routes/events.ts, shared/api/test/ownership.db.test.ts and shared/simulator/send-event.ts`            | A working authenticated event API with cross-merchant rejection. Milestone: Protected merchant flow.                  |
| [10](../weeks/week-10.md) | `shared/web/src/App.tsx, shared/web/src/EventList.tsx and shared/api/src/routes/events.ts`                            | Typed UI components and bounded safe API responses.                                                                   |
| [11](../weeks/week-11.md) | `shared/web/src/api.ts, shared/web/src/App.tsx and shared/delivery/browser-flow.md`                                   | A signed-in merchant can inspect its own persisted events through React.                                              |
| [12](../weeks/week-12.md) | `shared/api/test/, shared/database/README.md and shared/delivery/test-matrix.md`                                      | A coherent test matrix, one exercised transaction and corrected weak cases.                                           |
| [13](../weeks/week-13.md) | `shared/api/src/app.ts, shared/api/test/, shared/web/src/App.tsx and .github/workflows/checks.yml`                    | Bounded endpoints, redacted diagnostic logs and deliberate client errors.                                             |
| [14](../weeks/week-14.md) | `shared/delivery/incident.md, shared/database/migrations/ and shared/delivery/runbook.md`                             | An evidence-led repair, an explained query plan and a corrected runbook.                                              |
| [15](../weeks/week-15.md) | `shared/delivery/runbook.md, shared/delivery/final-architecture.md, shared/delivery/demo.md and README.md`            | A reproducible local product, an honest demo and attributable contribution evidence. Milestone: Independent handover. |

Create product modules at their named week. Keep the individual and shared applications separate: promotion adapts imports into shared modules, preserves authorship and adds the relevant tests. Shared code must not import a student workspace.

Use forward migrations after a migration has been shared. Shared authentication, ownership and database changes need maintainer review. The [application wiring guide](12-application-wiring.md) explains how the same tasks assemble the individual application.
